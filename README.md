# AyurNLP – AI-Powered Patient Case-Taking & Symptom Classification System

## 1. Project Overview
AyurNLP is a local academic prototype that accepts a free-text patient complaint and classifies it into one broad symptom category using the trained machine-learning implementation in `AyurNLP_implementation.ipynb`.

## 2. Problem Statement
**Patient Case-Taking Software**

## 3. Objective
To demonstrate an NLP and machine-learning workflow for organizing patient-reported complaints into predefined broad symptom categories.

## 4. Features
- Free-text complaint input
- Lowercase and surrounding-whitespace preprocessing
- TF-IDF text vectorization
- Logistic Regression classification
- Model probability estimate shown as confidence
- Input validation and API error handling
- Responsive local browser interface

## 5. Technology Stack
- Python
- Flask and Flask-CORS
- HTML, CSS, JavaScript
- Pandas, NumPy, scikit-learn

## 6. AI/NLP Methodology
The notebook creates a prototype dataset, preprocesses complaint text by converting it to lowercase and stripping surrounding whitespace, fits a default `TfidfVectorizer`, and trains `LogisticRegression(max_iter=1000)`. The exported `model.pkl` and `vectorizer.pkl` are produced from those notebook objects.

## 7. System Workflow
Patient complaint -> preprocessing -> saved TF-IDF vectorizer -> saved Logistic Regression model -> predicted category and highest `predict_proba()` value -> JSON API response -> browser result card.

## 8. Symptom Categories
- Respiratory
- Digestive
- Skin
- Musculoskeletal
- General

## 9. Dataset
The prototype uses only 20 manually created sample complaints, with four examples in each category. This dataset is for demonstration and cannot be considered clinically validated.

## 10. Model
The model is the Logistic Regression object trained in the notebook. Confidence is the highest machine-learning probability estimate for a prediction; it is not medical certainty.

## 11. Frontend
`frontend/index.html`, `style.css`, and `script.js` provide the complaint form, loading state, result card, supported categories, validation, clear action, and disclaimer. Predictions are never hard-coded in JavaScript.

## 12. Backend
`backend/app.py` loads `model.pkl` and `vectorizer.pkl`, exposes `POST /predict`, validates JSON input, applies the notebook preprocessing, and returns `category` and `confidence`. `GET /health` provides a simple local health check.

## 14. Installation
From the project directory:

```powershell
C:/Python314/python.exe -m pip install -r requirements.txt
```

A virtual environment is recommended for a separate installation.

## 15. How to Run
Start Flask from the project directory. Flask serves both the frontend and the prediction API:

```powershell
C:/Python314/python.exe backend/app.py
```

Open <http://127.0.0.1:5000> in a browser.

## 16. Sample Input
```json
{"complaint": "I have stomach pain and nausea"}
```

## 17. Sample Output
The category and probability are generated by the exported model at runtime. A response has this shape:

```json
{"category": "<model output>", "confidence": 0.0}
```

## 18. Limitations
- Only 20 manually created sample complaints are available.
- The dataset is too small for reliable generalization.
- Results are broad category classifications, not diagnoses.
- No clinical validation, patient history, database, or treatment functionality is included.

## 19. Future Scope
Future enhancements may include larger datasets, improved NLP, comparison of additional ML models, multilingual input, voice input, patient history, database integration, web deployment, and improved healthcare workflow integration.

## 20. Medical Disclaimer
This prototype performs broad symptom-category classification and does not provide medical diagnosis, treatment, or clinical decisions. It must not be used as a substitute for qualified medical advice.
